ALPHA MATE - TARGETED LIVE / PARTY FIXES

Base archive: AlphaMate_Latest_Update_Download.zip supplied in this conversation.

Changes in this source update:
1. Solo Live heart counter was moved out of the fixed top-right overlay that overlapped the close/exit controls. A dedicated, tappable heart action now sits beside the viewer count in the top action row for both host and viewer perspectives. It uses the existing liveHeartService and shared real-time counter; existing double-tap reactions remain intact.
2. Party remote audio playback no longer force-enables receiver MediaStreamTracks when an audio track emits `unmute`. The local audio element is resumed while publisher mute state remains authoritative. This avoids overriding the remote track state.
3. SFU publishing now attempts to prioritize microphone audio over video and apply a conservative adaptive video sender cap (1.2 Mbps / 24 fps) where the Android WebView/browser supports RTCRtpSender.setParameters. Unsupported implementations fall back to browser defaults.
4. Solo Live and Party startup now run backend health validation and TURN credential retrieval concurrently after Firebase authentication, rather than serially waiting for both.
5. GitHub Android build workflow now uses Node 24.12.0 to match package.json and current Firebase dependency engine requirements.

Preservation:
- Existing navigation, room layouts, host/viewer roles, filters, gifts, chat, seats, and existing animations were not intentionally redesigned or removed.
- Existing Cloudflare SFU / TURN architecture is retained; no alternate provider added.
- Existing Firestore heart service and double-tap interaction are retained.
